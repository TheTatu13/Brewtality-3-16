# Definition of Done — a new derived scraper

A scraper generated by `setup.py`/`setup.js` isn't "done" at the first green
CI run. This is the checklist a new scraper must clear before it's
considered a real member of the fleet, not a half-finished draft. Most of
it is enforced automatically (marked ✅ auto); a few things need a human or
a `gh` command once (marked ☐ manual).

## Code and tests

- [ ] ✅ auto — `pytest -q` / `npm test` all green, including
      `tests/consistency/*` (these run in CI on every push via
      `tests-reusable.yml`/`tests.yml`).
- [ ] ✅ auto — `tests/consistency/test_no_leftover_placeholders` (Python) /
      `no-leftover-placeholders.test.js` (JS) passes — no stray
      `{{PLACEHOLDER}}` tokens anywhere.
- [ ] ☐ manual — selectors in `config/scraper.json` actually tuned against
      the real careers page, not left on the generic fallbacks `setup.py`
      offered (the self-healing cascade means a wrong selector won't
      necessarily *fail* — check the first real scrape's job count looks
      right, don't just check it's green).

## Workflows (all ✅ auto-checked by `tests/consistency/test_repo.py` ::
`test_required_workflows_exist` / `required-workflows.test.js`)

- [ ] `scrape.yml` — calls `scrape-reusable.yml@v1`, dry-run gated on
      `event_name == 'workflow_dispatch'` (never on `inputs.dry_run` alone —
      that's empty-string-truthy-bug territory on a `schedule` trigger).
- [ ] `tests.yml` — calls `tests-reusable.yml@v1`.
- [ ] `automation-template-sync-check.yml` — present, and actually able to
      find updates (it hardcodes `TheTatu13/Brewtality-3-16` + the correct
      per-language `CHANGELOG.md` path; it does **not** rely on GitHub's
      `template_repository` metadata, which is never set for a repo created
      by `gh repo create --source=.`).
- [ ] `automation-health-summary.yml` — present, calls
      `health-summary-reusable.yml@v1`.
- [ ] `job-deep-validate.yml`, `job-recovery-from-disaster.yml` — present
      (copied as-is from the template).

## Repo metadata (☐ manual — `gh repo create` doesn't set any of this)

- [ ] Topics: `job-seeker-ro-spider`, `peviitor-ro` (see
      `ai/UPDATE-REPO-ABOUT.md`).
- [ ] Homepage set to the GitHub Pages URL.
- [ ] Description set (`Scraper pentru <Company> - peViitor.ro`).
- [ ] GitHub Pages enabled, serving from `main` / `/docs`.
- [ ] **Branch protection on `main`**: block force-push + branch deletion
      (no PR/review required — this fleet pushes directly to `main`).
      `setup.py`/`setup.js` now print the exact `gh api` command for this;
      it isn't automatic because the repo doesn't exist yet when the script
      runs.

## Documentation

- [ ] `CHANGELOG.md` has a real first-release entry (not just the
      template's own inherited history).
- [ ] `COMMIT_CHECKLIST.md` present (comes along automatically — not listed
      in the derivation script's own deletion list — but check after a
      `setup.py`/`setup.js` update in case that changes).

## First real run

- [ ] Trigger `scrape.yml` manually once (`workflow_dispatch`, dry-run
      first, then a real run) rather than waiting for the first scheduled
      cron fire — cheaper to catch a broken selector or a missing secret
      now than a day later in an `autoheal` issue.
- [ ] Trigger `automation-health-summary.yml` and
      `automation-template-sync-check.yml` manually once too, purely to
      confirm they run at all on a brand-new repo (both are read-only
      against run/version history, so this is safe to do anytime).
